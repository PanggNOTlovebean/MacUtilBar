# 1.0.0 (1) 开发候选验证 — 2026-11-15

**结论：可以构建、打包和发布预发布附件；不满足正式 1.0.0 全部验收。**

## 已执行

- `swift test`：9 项 XCTest，通过。覆盖配置往返/非法值/外部冲突、分区与刘海几何、隐藏窗口坐标判定及连续两次失败、自动收起暂停、URL 路由、快捷键语法、版本/plist 一致性和模板图标。
- `./Scripts/build.sh build/candidate`：通过，macOS 14 最低版本，arm64 + x86_64 通用二进制；原生 App 图标、Info.plist、ad-hoc 签名及 PKG。
- `codesign --verify --deep --strict build/candidate/MacUtilBar.app`：通过。
- `pkgutil --payload-files`：只包含 Applications/MacUtilBar.app；包不带安装脚本，组件禁止路径重定位。安装器自身未签名、应用未公证。
- 使用 `MACUTILBAR_CONFIG` 指向仓库 build/test-config.toml，不接触其他项目配置。没有请求或变更宿主辅助功能、录屏、TCC，没有重启其他应用。
- 宿主 macOS 26.6.2 (25G83)、1470×956 刘海屏。通过 `--diagnose` 添加自己的 ◇ 测试状态项，不移动其他应用图标，不发送模拟输入。

## 真实坐标证据与关键限制

最终通用可执行文件从 App 中复制为独立程序后执行，见 [standalone/host-frames.json](1.0.0/standalone/host-frames.json)：

| 状态 | 主图标 x | 测试图标 x | 结果 |
|---|---:|---:|---|
| 全部展开（前） | 1229 | 1127 | 在屏幕上 |
| 收起 | 1229 | -2231 | 测试项移出屏幕，主图标保留 |
| 普通展开 | 1229 | -569 | 永久隐藏区仍在屏外 |
| 全部展开（后） | 1229 | 1127 | 恢复原位置 |

`NSStatusItem.length` 设置不是成功依据，上述数据来自窗口坐标采样。自检使用 CG 窗口快照判断目标是否离屏。

**应用包启动路径未通过**：当前环境直接执行 `.app/Contents/MacOS/MacUtilBar` 以及 `open` 启动时，多次取得主图标 `(0,-22,42,22)` 等占位 frame，无法完成有效坐标验证；记录见 [host-frames.json](1.0.0/host-frames.json)。独立二进制与应用包使用同一实现。根因尚未确定，不能以独立程序成功推断安装后的 .app 一定正常。应用已加入保护：无有效坐标时停止折叠、打开设置并提示重新检查。

尝试临时改变自身状态项宽度，以 CG window 的唯一宽度变化定位自身窗口；不匹配时不猜测、不借用其他应用身份。此方法没有解决当前应用包环境限制。

## UI

归档 [standalone/](1.0.0/standalone/) 下中英文、General/Layout、Aqua/DarkAqua 共 8 张 620×520 内容区快照。快照由自身 NSView 渲染，不截取别的应用画面，不需要录屏权限。基本设置采用滚动区；仅检查了静态可见区域，未把未滚动区域、VoiceOver、Tab 顺序认定为完整验证通过。

## VM 尝试

通过 Computer Use 打开现有 VirtualBuddy 的 MacUtils Screenshot Lab，能取得客机桌面截图。⌘Space 未呈现可确认的新窗口；点击 Terminal dock 两次返回 `noWindowsAvailable`。尝试窗口 Raise、退出全屏后仍不能可靠交互。未向未知焦点粘贴命令，未修改既有共享目录、其他项目或客机应用。

因此 **VM 安装和折叠未验证**。没有把工具返回值或打开 VM 的动作当作验收。

## 仍未通过的验收

- 安装 PKG 后应用包的正常状态项显示/折叠；宿主 .app 坐标问题。
- VM 菜单栏折叠、跨显示器/错位屏幕；Intel 与 macOS 14 真机运行。
- 悬停/滚动/快捷键冲突、锁屏/睡眠恢复、菜单离开自动关闭的完整实机交互矩阵。
- 真实被刘海挡住的第三方图标计数精度，以及隐藏窗口不在 on-screen 列表时的补充检测。
- 登录项注册/批准/注销与安装器执行；未为了验证而安装到宿主 Applications。
- 辅助功能识别属于 1.1，不含在本阶段实现或验证中。
